## NGINX Service set up

**1. NGINX intalation:**
 
For systems baseded in Debian or Ubuntu, the instalation of NINX is carried out using the following command:

```bash
sudo apt update && sudo apt upgrade
```

```bash
sudo apt-get install nginx
```

This command download, install and initialize automaticly the Nginx service. After installing, put enable nginx daemon, and check the state using this command:

```bash
sudo systemctl enable --now nginx
```

```bash
sudo systemctl status nginx
```

**5. Create a dedicated NGINX site configuration**

The default Ubuntu installation includes a website configuration in:

```bash
/etc/nginx/sites-available/default
```

The site configuration file is created for NorthTech Operations. Create the new site configuration:

```bash
sudo nano /etc/nginx/sites-available/northtech-ops
```
The configuration added to this file:

```bash
server {
    listen 80;
    listen [::]:80;

    server_name _;

    root /var/www/northtech;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    access_log /var/log/nginx/northtech-ops-access.log;
    error_log /var/log/nginx/northtech-ops-error.log;
}
```

The co figuration of this file:

- server {} defines one web server configuration.
- listen 80 tells NGINX to receive HTTP connections on TCP port 80.
- server_name _ is used temporarily because the laboratory does not have a public DNS name yet.
- root /var/www/northtech defines where the website files are stored.
- index index.html defines the default page.
- location / defines how requests to the website are processed.
- try_files checks that the requested file or directory exists. If it does not exist, NGINX returns HTTP 404.
- access_log records client HTTP requests.
- error_log records errors generated by this website.

The server_name value will be changed later when DNS and TLS are configured.


**6. Enable the NorthTech operations site**

NGINX on Ubuntu uses symbolic links between sites-available and sites-enabled.

Enable the NorthTech configuration:

```bash
sudo ln -s /etc/nginx/sites-available/northtech-ops /etc/nginx/sites-enabled/northtech-ops
```

Check the symbolic link:

```bash
ls -l /etc/nginx/sites-enabled/
```

The site configuration remains stored in:

```bash
/etc/nginx/sites-available/northtech
```

and the symbolic link tells NGINX that the site is enabled.


**7. Disable the default Ubuntu website**

The default configuration is no longer required because NorthTech Ops Center becomes the active website.

Remove only the symbolic link:

```bash
sudo rm /etc/nginx/sites-enabled/default
```

The original configuration is kept in:

```bash
/etc/nginx/sites-available/default
```

This means that the default site is disabled but its original configuration is not deleted.

**8. Validate the NGINX configuration before applying it**

Before reloading NGINX, the configuration must be checked for syntax errors:

```bash
sudo nginx -t
```

if the result is correct should include:

```bash
syntax is ok
test is successful
```

This validation is important before changing a running service. A configuration error could stop NGINX from working correctly.

Only after a successful test, reload NGINX:

```bash
sudo systemctl reload nginx
```

reload applies the new configuration without performing a full service stop and start.

**10. Creating a TLS certificate**

Create a directory to store the TLS certificate and private key:

```bash
sudo mkdir -p /etc/nginx/tls
```

Create a self-signed X.509 certificate and a RSA private key:

```bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/nginx/tls/northtech-ops.key -out /etc/nginx/tls/northtech-ops.crt
```

The main options of the command are:

req: creates a certificate request.
- x509: creates an X.509 self-signed certificate.
- nodes: creates the private key without a password. NGINX can start without asking for a password.
- days 365: the certificate is valid for 365 days.
- newkey rsa:2048: creates a new 2048-bit RSA private key.
- keyout: defines where the private key is stored.
- out: defines where the certificate is stored.

OpenSSL asks for information about the certificate. The information will be about the organisation NorthTech Operations.

The private key must only be accessible by the administrator:

```bash
sudo chmod 600 /etc/nginx/tls/northtech-ops.key
```
The certificate is public information, so it can have read permissions:

```bash
sudo chmod 644 /etc/nginx/tls/northtech-ops.crt
```

Check the certificate information:

```bash
sudo openssl x509 -in /etc/nginx/tls/northtech-ops.crt -noout -subject -issuer -dates
```
This command shows the certificate owner, issuer and validity dates.

**11. Configure HTTPS**

First edit this the next file to .......................

```bash
sudo nano /etc/nginx/sites-available/northtech-ops
```
And add 

```bash
server {
    listen 80;
    listen [::]:80;

    server_name _;

    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;

    server_name _;

    root /var/www/northtech-ops;
    index index.html;

    ssl_certificate /etc/nginx/tls/northtech-ops.crt;
    ssl_certificate_key /etc/nginx/tls/northtech-ops.key;

    ssl_protocols TLSv1.2 TLSv1.3;

    location / {
        try_files $uri $uri/ =404;
    }

    access_log /var/log/nginx/northtech-ops-access.log;
    error_log /var/log/nginx/northtech-ops-error.log;
}
```

them:

```bash
sudo nginx -t
```

if there are not errors

```bash
sudo systemctl reload nginx
```



Final checking:

```bash
ss -lntp | grep -E ':80|:443'
```
```bash
curl -I http://localhost
```
```bash

```
```bash

```

**12. Nginx hardening**

Add headers in this configuration file in HTTPS block

```bash
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

inside `server`block limitate the size:

```bash
client_max_body_size 10M;
```

validate before apply:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

```bash
curl -k -I https://localhost
```

```bash
ldd /usr/sbin/sbin/nginx | grep "libwrap"
```
